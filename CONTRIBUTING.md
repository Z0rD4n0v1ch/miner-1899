# Как устроена работа над «Шахтёр 1899»

Правила проекта — для автора, для помощников и для всех, кто хочет прислать исправление. По-английски игра называется **Miner 1899**; так же называются репозиторий и файл игры.

## Если хочешь помочь

- **Нашёл ошибку** — открой [Issue](https://github.com/Z0rD4n0v1ch/miner-1899/issues): что делал, что ожидал, что вышло. Очень помогают скриншот, видео или файл сохранения («Экспорт» в игре) и версия игры — она в заголовке рядом с названием.
- **Есть идея** — тоже Issue. Крупные идеи сначала обсуждаем, потом делаем: решения по игре принимает автор.
- **Хочешь прислать исправление** — сделай fork, внеси правку, прогони тесты (см. ниже) и открой Pull Request с описанием, что и зачем изменено.

Присылая код, ты соглашаешься, что он распространяется под лицензией проекта — **GNU AGPL-3.0** (версии 3 или более поздней).

## Как устроена игра

1. **Один файл** `miner-1899.html` — HTML, CSS и JavaScript без сборки и без внешних библиотек. Он работает и с компьютера (двойной щелчок), и с сайта, и из Telegram.
2. **Игра не обращается в сеть сама.** Только когда игрок включает радио или видео. Скрипт Telegram подключается только внутри Telegram.
3. **Всё должно работать в Windows 10.** Никаких эмодзи и возможностей, которых там нет; например, монета нарисована стилями, а не символом 🪙.
4. **Сохранения не ломаются.** `SAVE_VERSION` растёт только при смене формата, старые сохранения переводятся в новый формат и загружаются. Повреждённый файл отклоняется, а текущая игра остаётся нетронутой.
5. **Режим отладки** — только по адресу с `?debug=1`. В игре, где его включали, достижения не выдаются.
6. **Названия:** по-русски — «Шахтёр 1899» (игра, русский README, русская страница), по-английски — «Miner 1899».

## Тесты

Каждое изменение — с тестами. Тесты — файлы `*.test.js`; они запускают настоящий `miner-1899.html` в песочнице Node.js:

```bash
node physics.test.js          # один файл
for t in *.test.js; do node "$t" | tail -1; done   # все
```

Перед отправкой должны проходить **все**. `sync.sh` и `update-all.sh` прогоняют их сами и при любой ошибке ничего не отправляют.

## Коммиты и отправка

- Формат сообщения: `feat:` новое · `fix:` исправление · `docs:` документация · `chore:` служебное · `balance:` баланс — и коротко, по-русски, что сделано.
- Отправка — только через `./sync.sh push "сообщение"`. Скрипт сам забирает правки с GitHub и ставит твои коммиты поверх; при конфликте ничего не отправляет и не ломает.
- `sync.sh` добавляет в коммит строку `Assisted-by: Claude (Anthropic)` — проект делается с помощью Claude. Если правка сделана без него: `ASSISTED_BY= ./sync.sh push "…"`.

## Версии и выпуски

- **Номер `X.Y.Z`:** новые возможности поднимают среднюю цифру, исправления — последнюю, крупный шаг — первую (как 2.0.0). Номер в игре меняет сам выпуск, вручную его не правим.
- **Изменения копятся, версия выходит пачкой.** Всё новое записывается в `CHANGELOG.md` в раздел `[Unreleased]` — «Добавлено / Изменено / Исправлено». При выпуске раздел становится `[X.Y.Z] — дата`.
- **Планы** — в «Планируется» в CHANGELOG и подробно в `ROADMAP.md`.
- **Вместе с каждой версией обновляются:** README и CHANGELOG на GitHub, страница сайта и **все скриншоты** — и в `docs/screenshots/`, и на сайте.
- **Выпуск** — `bash ./update-all.sh` из папки, где лежат репозитории игры и сайта: тесты, отправка, тег, игра на сайте, «Что нового».
- **Страница выпуска на GitHub** создаётся сама (`.github/workflows/release.yml`): описание из CHANGELOG и файл игры для скачивания.
