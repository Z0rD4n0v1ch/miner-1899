# ⛏️ Miner 1899

2D-игра про шахтёра с процедурно генерируемой шахтой. Чистый HTML + Canvas + JavaScript — без сборки, без зависимостей, без npm.

**Играть:** открой `index.html` в браузере (или включи GitHub Pages — см. ниже).

## Возможности

- **Процедурная генерация** мира 50×100 блоков по seed
- **Ресурсы**: земля, камень, золото, алмазы, рубины — чем глубже, тем ценнее
- **Опасности**: лава (телепорт наверх и −50 очков), пещеры
- **Физика**: гравитация, прыжки, коллизии по тайлам
- **Камера** следит за игроком
- **Сохранения**: 3 ручных слота, автосохранение каждые 30 секунд, экспорт/импорт в JSON
- **Компрессия** мира через RLE — сохранения занимают в разы меньше места

## Управление

| Клавиша | Действие |
|---|---|
| `WASD` / `←↑→↓` | Движение |
| `Пробел` | Копать блок перед собой (или под собой — с `S`) |
| `ESC` | Меню сохранений |

## Как играть

1. Копай вниз — чем глубже, тем дороже руды.
2. Собирай золото (10 очков), алмазы (50), рубины (100).
3. Не падай в лаву.
4. Сохраняйся через `ESC` — прогресс пишется в `localStorage` браузера.
5. Экспортируй сохранение в JSON, если хочешь перенести прогресс на другое устройство.

## Локальный запуск

Никакой сборки не нужно — просто открыть файл:

```bash
git clone https://github.com/Z0rD4n0v1ch/miner-1899.git
cd miner-1899
open index.html          # macOS
# xdg-open index.html    # Linux
# start index.html       # Windows
```

Если браузер ругается на `file://` (некоторые политики безопасности), подними локальный сервер:

```bash
python3 -m http.server 8000
# затем http://localhost:8000
```

## Публикация на GitHub Pages

Workflow уже лежит в `.github/workflows/deploy.yml` — он публикует игру при каждом пуше в `main`.

Один раз включи в настройках репозитория:

**Settings → Pages → Build and deployment → Source: GitHub Actions**

После пуша игра будет доступна по адресу `https://Z0rD4n0v1ch.github.io/miner-1899/`.

## Синхронизация с GitHub — `sync.sh`

В проекте лежит скрипт, который закрывает весь цикл работы с репозиторием. Запускать из папки проекта.

```bash
./sync.sh doctor            # проверить готовность: git, ключи, доступ
./sync.sh init              # первая загрузка на GitHub
./sync.sh push "feat: кирки"  # закоммитить правки и отправить
./sync.sh release 1.2.0     # выпустить версию: bump + тег + push
./sync.sh pull              # забрать изменения с GitHub
./sync.sh status            # ветка, коммиты, теги, расхождение
./sync.sh pages             # включить GitHub Pages через gh
```

Что делает `release`: поднимает `GAME_VERSION` и версию в заголовке игры, проверяет наличие раздела в `CHANGELOG.md`, создаёт коммит и аннотированный тег, отправляет ветку и тег на GitHub. `SAVE_VERSION` не трогает — это делается руками и только при ломающих изменениях.

Настройка под свой аккаунт — через переменные окружения, менять код не нужно:

```bash
GITHUB_USER=ТвойНик REPO_NAME=другой-репозиторий ./sync.sh init
USE_HTTPS=1 ./sync.sh init        # если предпочитаешь токен вместо SSH
```

Если скрипт не запускается с ошибкой «Permission denied» — потерялся бит исполнения (бывает при распаковке zip):

```bash
chmod +x sync.sh
```

Развёрнутое руководство по первой публикации, включая разбор ошибок авторизации, — в [GITHUB_SETUP.md](GITHUB_SETUP.md).

## Версионирование

Проект следует [SemVer](https://semver.org/lang/ru/). Две версии ведутся раздельно:

- `GAME_VERSION` — версия игры, растёт при любом обновлении.
- `SAVE_VERSION` — версия **формата сохранений**. Повышается только если старые сохранения перестают читаться. Это защищает прогресс игроков от ломающих изменений.

Переименование проекта — пример изменения, которое **не** трогает `SAVE_VERSION`: формат данных не изменился, значит сохранения игроков продолжают работать.

Все значимые изменения — в [CHANGELOG.md](CHANGELOG.md).
